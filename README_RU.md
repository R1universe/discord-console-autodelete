# Discord AutoDelete v3.1 — инструкция (RU)

**Интерфейс по умолчанию теперь английский.** Скрипт открывает плавающую панель в Discord Web, позволяет включить/приостановить автоматическое удаление своих новых сообщений и настроить задержку и область действия.

> **Предупреждение:** это неофициальная автоматизация пользовательского аккаунта, нарушающая правила Discord. Возможна блокировка. Стабильная работа в живом Discord **не подтверждена**: пройдены только автоматизированные тесты на имитациях клиента.

## Быстрый запуск

1. Прочитай весь [autodelete.js](./autodelete.js), не запускай непроверенный код из случайных источников.
2. Открой [Discord Web](https://discord.com/app) и консоль браузера: на Mac в Chrome `Cmd + Option + J`.
3. Скопируй содержимое `autodelete.js` и вставь в Console. Никакого токена вводить не нужно.
4. В панели установи задержку: пресеты 5, 10, 30, 60 секунд или вручную 2–86400 секунд.
5. Выбери **Everywhere / Servers only / DMs only** и нажми **Enable auto-delete**.
6. Проверь работу на безобидном сообщении.

## Команды (необязательные)

```js
DiscordAutoDelete.status()        // состояние и мониторинг
DiscordAutoDelete.setDelay(30)    // задержка для новых сообщений
DiscordAutoDelete.setScope("dm") // all, servers, dm
DiscordAutoDelete.pause()         // остановка и отмена очереди
DiscordAutoDelete.resume()        // включить
DiscordAutoDelete.retry()         // попытка переподключения
DiscordAutoDelete.stop()          // полное удаление панели
```

## Почему теперь другой способ подключения?

В предыдущих версиях код требовал конкретный `FluxDispatcher`, которого текущая сборка Discord не обнаруживала — ошибка `FluxDispatcher: 0 вариантов`.

В v3/v3.1:
- поиск экспортов Webpack расширен, в v3.1 объединены модули нескольких runtime и добавлена проверка вложенного `HTTP` в экспорте с `getAPIBaseURL`;
- вместо `REST=false` теперь показывается количество кандидатов: ранее неоднозначность ошибочно выглядела как отсутствие модуля;
- у `FluxDispatcher` больше нет статуса обязательного компонента;
- резервный режим читает **MessageStore в текущем открытом канале** — это ограниченный режим, **не работает глобально во всех чатах**;
- удаление использует встроенный клиентский `RestAPI.del` (если найден) либо `MessageActions.deleteMessage`;
- при невозможности безопасного подключения **автоудаление остаётся выключенным**.

**Токен отдельно не требуется**, поскольку вызов выполняется внутри уже авторизованного Discord. Это не означает, что запросы не требуют авторизации — Discord использует текущую сессию.

## Ограничения

- В резервном режиме отслеживается только открытый канал; при переходах между каналами сообщения могут пропускаться.
- После перезагрузки страницы или закрытия вкладки скрипт прекращает работу, все таймеры теряются.
- Включение всегда ручное. Настройки задержки и области сохраняются в браузере.
- Сообщения, отправленные до включения, не удаляются; история чатов не сканируется.
- Собеседник или другой бот может сохранить сообщение до удаления.
- Отказ Discord API и лимиты запросов не гарантируют удаление ровно в срок.
